# v3.0 加密发布包说明（防抄袭 / 防拷走）

> 需求：防止有人盗用课题结果，把代码加密后重新打包，版本号 **3.0**。
>
> 先说清楚能做到什么、不能做到什么——这类保护最忌讳吹牛。

## 1. 能做到 / 不能做到

**能（本次实现）**
- 包内**没有明文源码**：`payload.bin` 是加密负载，直接拷走文件夹只能拿到密文；
- 运行时才解密到**随机临时目录**，退出（Ctrl+C/关窗口）即删除；
- `payload.bin` 带 **HMAC-SHA256 完整性校验**，改一个字节就启动失败（防篡改、防"加料"）；
- 每个构建有**唯一 Build ID**，源码与前端里注入**版权水印首行**，抄的人只要留着文件就能被追溯；
- 附带 `LICENSE.txt`（允许参赛/课堂演示，禁止改头换面提交或商用）。

**不能**
- 不可能阻止有决心的人逆向：Python 程序运行时必须把代码还原到内存/磁盘，浏览器必须能读到 JS。
  所以这是"**提高门槛 + 可追溯**"，不是"理论不可破解"。任何声称"绝对加密"的说法都是骗人的。
- 前端 JS 在浏览器里永远是明文（DevTools 可见），所以前端只做水印，不做加密承诺。

## 2. 包结构（v3.0）

```
ReactionProtocol-PC-3.0/
  bootstrap.py      启动器（唯一明文 .py）：校验→解密→临时目录运行→清理
  payload.bin       加密负载（≈200KB）：server.py + game/*.py + data/*.json + public/*
  start.sh          启动脚本（LF + 755，指向 bootstrap.py）
  start.bat         Windows 启动脚本
  LICENSE.txt       版权与许可（含 Build ID）
  启动说明.md / 使用说明.md
  save/             首次运行后生成（存"该 IP 已通关教程"等运行期状态）
```

加密算法（纯标准库，无第三方依赖）：
- 密钥 = `PBKDF2-HMAC-SHA256(口令, 随机 16B 盐, 60000 轮)`；
- 密文 = 负载 XOR `SHA256(密钥‖块序号)` 密钥流（每块 32B）；
- 头部 = `RP30` + 盐 + HMAC-SHA256 标签；口令在启动器里拆段存放。

## 3. 水印与可追溯

- 构建时给**每个 .py / .js / .css** 注入首行：
  `© 2026 北京市建华实验学校 · 研创杯 · Reaction Protocol v3.0 | 未经许可禁止复制/传播 | build=<时间戳-随机>`
- 启动器与开场 banner 也打印版权行；`/status.json` 增加 `"version": "3.0"`。
- 若在别处看到同名水印或同一 Build ID，即可判定来源（这正是"防盗用"最有用的部分）。

## 4. 玩家侧体验变化

- 双击 `start.bat` / `bash start.sh` 后多一行"正在解密游戏数据 ..."，约 0.2–0.5 秒；
- 其余完全一样：浏览器开 `http://localhost:8765`，教程、AI、联机、换图都在；
- 存档（教程通关记录）落在启动器旁边的 `save/`，**不会**随临时目录消失。

## 7. 已知限制

1. 手机 APK 这轮**没有**做加密重打包（仍是 v1.2 的结构）；如果也要防抄，需要在 Chaquopy 侧把 `src/main/python` 换成加密负载 + 启动器解包（工作量另算，可后续做）。
2. 加密只保护"静态文件"；游戏运行时临时目录里的文件对同机管理员可见（这是本机运行的物理限制）。
3. 口令写在启动器里（拆段存放），属于"防顺手抄"级别；真要更强需要外部服务端授权/签名校验，会牺牲"机房离线可玩"这个核心优势，因此没有采用。
