## 5. 银河麒麟双击 `.sh` 会用编辑器打开——原因与解决

**不是脚本坏了，是 Linux 桌面文件管理器的安全策略**，三层原因：

1. **文件没有可执行位（最常见）**：从 U 盘/压缩包/Windows 拷过来的 `.sh` 常丢 `x` 位，没有 `x` 就是普通文本，双击=用编辑器打开。
2. **文件管理器把"可执行文本文件"的策略设成了"查看"**：麒麟的 UKUI/Peony、GNOME 的 Nautilus 都有这个设置，不少发行版默认就是"用编辑器打开"。
3. **曾经在三选一里选了"显示"并记住了**：之后双击就一直打开编辑器。

**四种解决办法**（详见包内 `启动说明.md`）：
1. 终端执行 `bash start.sh`（最稳，不依赖任何桌面设置）；
2. `chmod +x start.sh` 后再双击；
3. 改文件管理器策略：GNOME 系 `gsettings set org.gnome.nautilus.preferences executable-text-activation launch`；麒麟 Peony 右键属性 → 权限 → 勾"允许作为程序执行"（或右键"在终端中运行"）；
4. 建 `.desktop` 快捷方式（`Exec=bash /路径/start.sh`、`Terminal=true`）。

补充：本包的 `start.sh` 已按 **LF 换行 + `#!/usr/bin/env bash`** 编写，并在 zip 里保留了可执行位；如果解压工具丢了权限，重新 `chmod +x` 即可。另外 `start.sh` 会自动挑 `python3/python3.11/python`，找不到时提示 `sudo apt install -y python3`。

## 6. 已知限制

1. HUD 缩放是全局系数（0.74/0.72），没有做成可调设置；如果机房屏幕特别小还想更小，改 `public/ui.js` 里两个 `K` 即可（或用浏览器缩放）。
