### 0.1 内嵌实现要点

- `server.py` 可内嵌化：`ROOT` 由 `RP_ROOT`/参数决定，`configure(root,…)` 重定位静态资源与地图，`run_server(..., block=False)` 返回 `ServerHandle(.port/.ips/.urls()/.stop())`；PC 命令行行为不变（`python server.py 8791 --bots 1 --no-browser` 仍可用）。
- `host_runner.py`（`android/app/src/main/python/`）是 Java↔Python 的唯一桥：`serve()/status()/stop()`；**必须在 `import server` 之前设 `RP_ROOT`**。
- 资源双份：`assets/` 根放一份 `public/` 供 WebView 直接加载；另经 Gradle `Sync` 任务生成 `assets/public` + `assets/data`，首启解包到 `filesDir/host` 交给服务端当 root。解包戳 = `versionCode + lastUpdateTime`（只比 versionCode 会导致同版本重装时对外资源不刷新，已实测踩到并修复）。
- 前台服务 `HostService`：通知栏常驻（显示端口与 `http://ip:port`、可一键停止）、`PARTIAL_WAKE_LOCK` 息屏保活、`foregroundServiceType="dataSync"`；权限含 `FOREGROUND_SERVICE(_DATA_SYNC)`、`POST_NOTIFICATIONS`、`WAKE_LOCK`、`ACCESS_WIFI_STATE`。
- 局域网地址：`LanInfo` 直接从 WLAN/以太网接口取 IPv4（优先），Python 侧 `lan_ips()` 兜底 —— 避免"WiFi+移动数据同开"时把蜂窝内网 IP 发给同学。
- 电量/发热提示：通知副标题在低电（≤20% 未充电）或机身 ≥42℃ 时追加提醒。
- 客户端自动重连：`public/game.js` 的 `ws.onclose` 改为指数退避自动重连（0.4s×n，上限 8s），复用上次 `join`；服务端按 IP 恢复战绩（`save/restore_ip_stats`），重连成功后提示"已重新连接服务器，战绩已恢复"。

### 0.3 v1.2：开火键位置 / 60Hz 手机服 / 高 FOV / 全端换图倒计时

用户提出的四项手感与观感调整，全部真机验证（HUAWEI FOA-AL00，768×362 CSS 视口）：

| 需求 | 实现 | 真机实测 |
|---|---|---|
| 开火键移到"左手的中间位置"（用户选定：贴左边缘、垂直居中） | `public/mobile_layout.js`：`fire.cx = 左安全边+8+半径`、`fire.cy = VH/2`；功能键改贴**右**边缘竖排（换弹→烟雾→技能→开镜），把右侧整片留给瞄准 | 开火键中心 **(51, 181)**＝屏宽 6.6%、屏高 50%；`ML.report` overlaps=0、outOfSafe=[]、16 个可点元素；按住 700 ms 弹药 12→9、命中判定 `fire:fire`；开火键与摇杆仍留 15 px 间距 |
| 手机端服务器改 60Hz | `server.py`：`TICK` 可配（`configure(tick=)` / `--tick`），`host_runner.serve(tick=60)` 默认手机 60Hz，PC 默认仍 30Hz；`/status.json` 新增 `tick` | tick=60 下实测 **46.7–51.6 fps**（同一台手机、同为 4 AI 机器人；30Hz 目标时只有 26.9 fps）→ 实际逻辑帧率提升约 73%，10 秒丢 113 帧（约 20%） |
| 手机端 FOV 调高到至少看得见半个地图 | `public/game.js`：新增 `fovMode/fovScale()/cycleFov()/fovTag()`；手机默认 `area`＝半个地图，再按用户反馈（v1.2.1"fov 太大"）把线性视野缩到 80% → 面积占地图 **32%**；下限 clamp 到 cover（不露地图外）、上限 1.6；PC 默认 `orig` 维持 1:1 不变；入口＝手机顶部菜单第 4 键「视野」循环，或 `?fov=area\|width\|height\|orig\|<数字>`（记忆到 localStorage） | 默认档：缩放 **0.476**、视野 **1615×761**、占地图面积 **32.0%**（= 原 2018×951 的 80% 线性）；四档循环实测 视野½(32.0%) → 视野宽(0.8→960×452，11.3%) → 视野高(0.566→1357×640，22.6%) → 视野1:1(1.0→768×362，7.2%) |
| 全端加入地图切换倒计时 | 服务端快照新增 `ms`（距离下次换图秒数）；手机在地图名下方显示"换图 m:ss"（<30 s 变黄）；PC 左上角显示 `MAP // 名称 ⟳ 换图 m:ss` | 真机 `mapSwitchIn` 165.4→161.4（4 秒递减）、HUD 文本"换图 2:41"；PC 侧 `node tests/hud_runtime.js` 通过 |

**已知取舍（写清楚）**：
1. **视野档位的取舍**：默认档（32% 地图面积、缩放 0.476）下人物约 **15 CSS 像素宽**；首版按"半张地图面积"（50%、缩放 0.381）真机试玩后用户反馈"fov 太大"，因此把线性视野统一缩到 80%（`FOV_VIEW = 0.8`）。仍嫌小/嫌大可用「视野宽」(0.8) 或「视野高」(0.566) 档，或 `?fov=0.6` 这类数字直接给缩放值。
2. **手机 60Hz 是"目标帧率"而非保证**：手机 CPU 单核吃满，实测 46.7–51.6 fps。物理全部按 `dt` 计算（位移/子弹/AI 转向/回血），所以掉帧只影响手感不影响数值正确性；PC 上同版本 60Hz 实测 60.0 fps、lag=0。
3. 手机开服后**自己也要先填名字**才能加入对局（与 PC 端一致），空名会被"先给自己起个名字吧"拦住——真机自动化验收踩到过。

## 1. 架构

- 安卓端是 **WebView 外壳 + 仓库内 `public/` 资源**，不复制一份前端，避免版本漂移；
- 客户端入口 `public/mobile.html`（触屏版），通过 `?server=主机:端口` 连接 PC 上的权威服务端；
- 服务端仍是零依赖纯 Python（`server.py`），负责 30Hz 逻辑、化学引擎、AI 与地图轮换；
- 真机测试用 `adb reverse tcp:8765 tcp:8765` 走 USB，无需同一 WiFi；
- 局域网对战时在启动弹窗填 PC 局域网 IP（如 `192.168.1.5:8765`），长按屏幕可重设。

## 5. 真机发现并修复的问题

1. **`mobile.html` 缺少 `ui.js`**：手机端每帧抛 `uiFont is not defined`，HUD 无法绘制。已在 `mobile.html` 中按 PC 端顺序先加载 `ui.js`。
2. **开火键热区覆盖“聊天/管理”按钮**：开火键判定半径 `r+14` 与右侧按钮重叠，导致手机上聊天和管理点不开。已改为**先判圆形按钮、再判开火键**。
3. **全屏 Promise 未捕获**：部分 WebView 不支持 Fullscreen 时产生未处理拒绝；已加 `.catch()` 静默降级。
4. 为便于验收新增只读 `/status.json`（玩家位置/武器/弹药/pH/缓冲/统计/累计事件/补给点/换图倒计时），不影响游戏逻辑。

## 6. 手机端 UI 重做（v3 · 真机反馈后）

**问题**：手机横屏 CSS 视口只有 768×362，而 `game.js` 的 `UIS = Math.max(1, Math.min(VW/1366, VH/768))` 在手机上恒等于 1 —— PC 版按 1366×768 设计的 HUD（小地图 206×138、状态卡 380×164、试剂架 8 槽约 520px 宽）被**原尺寸**画进 768×362，与触控层（武器条、功能键、开火键、摇杆）大面积重叠；同时 `mobile.html` 开始界面的 `.panel/.sub/.help` 在 `style.css` 里没有对应样式。

**做法**

1. 新增 [`public/mobile_layout.js`](../public/mobile_layout.js)：布局单一真源。
   - `ML.compute(VW,VH,opts)` 统一计算比分条/状态条/武器条/开火键/功能键/摇杆与安全区（`env(safe-area-inset-*)` 自动探测）；
   - `ML.hit(layout,x,y)` 固定优先级 **菜单 > 功能键 > 武器条 > 开火 > 移动/瞄准分区**，从根上消除“开火键吃掉聊天/管理键”这类问题；
   - `ML.overlaps()/report()` 把布局变成可自动断言的数据，供 Node 多尺寸测试与真机 CDP 自检共用。
2. 重写 [`public/mobile.js`](../public/mobile.js)：手机端独立紧凑 HUD（顶部比分+地图+菜单、pH/缓冲/弹药状态条、右侧击杀播报、击杀确认、受击方向、提示条、HVT、低缓冲边框脉冲），以及手机版战绩板 / 管理面板 / 阵亡界面；触摸层显式 `setTransform(DPR)`，坐标即 CSS 像素。
3. `game.js` 在 `window.__MOBILE__` 时**不再调用任何 PC HUD**，改调 `drawMobileHud / drawMobileBoard / drawMobileAdmin / drawMobileDeath`，PC 路径保持原样（`tests/hud_runtime.js` 仍通过）。
4. 烟雾选点改为**可取消模态**：再按一次“烟雾”取消，并显示“点地图投放 / 再按烟雾取消”。
5. 开始界面补手机样式并在横屏小屏压缩，保证“开战”按钮首屏可见（实测面板 745×249、按钮中心 y=254 < 362）。
