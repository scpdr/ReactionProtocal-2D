# PC 端四项问题修复（v1.3）与验收记录

> 背景：手机端（v1.2）验收结束，回到电脑端。用户反馈四个问题：①机房电脑上明显卡顿、不跟手，但 CPU 没跑满；②AI 没人靠近就卡脚不动；③需要一个新手教程关卡（每个 IP 首次加入强制、通关后不再强制）；④F 泄露（氟泄漏）积分逻辑不完善，且需要"隐藏可用积分"。
>
> 本文记录**根因证据 → 改法 → 验证数据 → 已知限制**。测试命令都能直接复跑。

## 1. 卡顿 / 不跟手（不是 CPU 不够，是延迟链太长）

### 诊断证据（本机实测）
| 怀疑对象 | 实测 | 结论 |
|---|---|---|
| 服务端主循环太慢 | `Game.update + snapshot` 单帧 **0.03~0.06 ms**（4 AI 机器人 + 2 玩家） | 不是瓶颈 |
| 服务端帧率跟不上 | tick=30 实测 **30.0fps/lag=0**；tick=60 实测 **60.0fps/lag=0** | 不是瓶颈 |
| 前端 JS 绘制太慢 | 2730×1536 画布下 `render` **0.32ms**、`drawHUD` 0.03ms | 不是 JS 计算瓶颈 |
| **延迟链** | 30Hz 步进最多白等 **33ms** + 插值缓冲**死值 80ms** ≈ **113ms** | **主因**："不跟手"就是这个 |

另外 `time.sleep()` 在 Windows 默认定时器精度只有 ~15.6ms，弱机器上会把 1/30s 睡眠抖成 31/47ms 交替（"一卡一卡但 CPU 闲"）。

### 改法
1. **默认 60Hz**：`TICK` 默认 30 → **60**（`--tick 30` 或 `TICK=30` 可回退；手机端本来就是 60）。
2. **插值缓冲自适应**：`interpDelayMs() = clamp(快照间隔EMA × 1.55, 24ms, 80ms)` —— 60Hz 服务器下 **25.9ms**（原死值 80ms）。
3. **自己的位置不走插值缓冲**：`smoothSelf()` 直接向最新快照指数收敛（约 40ms 到位，不超调；重生/换图瞬移直接对齐）。只影响绘制，不参与判定。
4. **Windows 定时器精度 1ms**：`timeBeginPeriod(1)`（仅 Windows，服务端启动时调用），消除 sleep 抖动。
5. **自动降画质**：连续 3 秒 <45fps → `DPR` 降到 1（像素量 1/4）；可用 `?perf=1` 强制低画质、`?perf=0` 关闭自动降级。
6. **HUD 自检**：左上角显示 `FPS 60 · 16.7ms · 插值 26ms`（低画质时变黄），方便在机房机器上报数据。

### 验证
```
服务端（默认参数）：tick=60  fps=60.0  lag=0
浏览器（2730×1536，无头 Edge）：snapIvMs=16.6 → interpDelayMs=25.7；frameMs=7.8
node tests/pc_latency_check.js  → 17/17 通过
```
视觉延迟从 ≈113ms 降到 ≈**服务器步进(≤16.7ms) + 平滑(≈40ms)** 量级。

## 2. AI 没人靠近就"卡脚不动"

### 根因
训练策略（`LAN_AI_BOTS=1`）只在**看得见目标**时才有意义；没有目标时它输出"原地待机"，所以远离战斗的机器人一直站着。

### 改法
`_ai_patrol()`：连续 `AI_PATROL_AFTER=1.2s` 没有任何可打目标 → 由巡逻兜底接管移动：优先朝最近敌人方向游走（带随机偏移），否则随机巡逻；选点要求**不在墙里且直线可见**（避免一直撞墙）；一旦策略重新看到目标，移动权立刻交回策略（**对局强度不变**，只是补了"找人"）。

### 验证
| 场景 | 改前 | 改后 |
|---|---|---|
| 场上只有 4 个训练策略机器人、无真人，8 秒位移 | 全部 **0 px** | **440 / 549 / 1079 / 1527 px** |
| 单测：4 个机器人都拿到巡逻方向+路径点 | — | **4/4**（`tests/v13_server_check.py`） |

## 3. 新手教程（独立关卡：独立小地图 + 每个玩家一个私有小局）

### 架构：教程不是在对战地图里"上保护"，而是真的开一个独立小局
- **独立小地图**：`data/maps.json` 新增 `tutorial`（`"tutorial": true`，**1100×700**，"TRAINING LAB"），有墙、出生点与一个补给点。带 `tutorial` 标记的地图**永远不参与对战轮换**（`switch_map` 过滤）。
- **每个玩家一个 Game 实例**：服务端在 `start_tutorial_session()` 里为进场玩家新建一个私有 `Game`（自己 + 3 个静止人机靶子），**看不到主对局、也看不到别的教程玩家**。
- **为什么用"模块副本"**：地图/墙体/世界尺寸在 `server.py` 里是模块级全局变量（`apply_map` 改 `WORLD_W/WALLS`），同一个模块里没法让"教程小地图"和"对战大地图"同时存在。所以教程单独 `importlib` 加载一份 `server.py` 副本（它有自己的一套全局状态），在副本里给每个玩家各开一个 Game。副本懒加载一次，大厅里所有教程玩家共用这一份副本的游戏们（同一张小地图）。
- **消息/快照路由**：连接 id 用 `900001+` 命名空间（避免与主对局 pid 冲突）；`game_loop` 每帧额外推进每个教程小局，并把它的快照**只发给该玩家**；`handle_message(pid, msg, game=教程局)` 让输入/技能/聊天都落在自己的小局里。
- **进出流程**：`join` 时若该 IP 未完成教程 → 回 `{"t":"tut_start","id","map":教程地图}`（客户端 `applyMap` + `TUT.begin()`，世界变成 1100×700）；通关/跳过 → 客户端发 `tut_done` → 服务端销毁小局、把玩家加入主对局、回 `{"t":"joined"}` + `{"t":"map"}`（世界切回 2400×1600），并记录该 IP。
- **靶子**：`TUT_DUMMIES` 3 个（pistol / rifle / sniper，其中一个缓冲只有 55 便于练习"剥缓冲→补刀"），`dummy=True` → 不思考、不移动、不开枪、只挨打，死了按出生点自动复位。

### 教程内容（8 步互动，`public/tutorial.js`）
Canvas 绘制，PC 右侧面板（宽 30–40% VW，避开 pH 表盘/小地图/试剂架）；手机端底部窄条（避开 mobile_layout 全部控件）。每步 = 机制说明 + 真实操作判定：
1. 移动（累计 ≥300px）→ 2. 开火（≥3 发）→ 3. 换弹+切枪 → 4. **pH 与缓冲**（命中靶子 1 次）→ 5. **三通道与克制**（切到氧化通道开火）→ 6. **中和救援/补给**（用指示剂或补给点）→ 7. **技能三件套**（烟雾 E / AOE Q / 指示剂 F 任一）→ 8. **积分、隐藏可用积分与地图轮换**（点"开始对战"）

### 验证
```
python tests/tutorial_private_check.py  → 19/19：教程地图存在且 ≤1400×900、轮换池不含它、
                                          两个会话是不同 Game、甲看不到乙的名字/id、
                                          3 个靶子全 bot+dummy、2 秒内 0.000px 不动、0 子弹、
                                          副本全局被搞乱后新会话仍强制回到教程小地图
node tests/tutorial_check.js            → 120/120（8 步文案 + 判定 + 手机端布局）
python tools/tutorial_e2e_probe.py      → 16/16（真浏览器）：
    进局 → mapId=tutorial、世界 1100×700、4 人（自己+3 靶子）、主对局里看不到他；
    通关 → mapId=titration、世界 2400×1600、教程小局销毁(0)、tutorials≥1、已加入主对局；
    同一 IP 重进 → 直接进对战地图，不再强制教程
```

## 4. 氟泄漏：隐藏可用积分（不再出现"3 万分后一直可用 / 6 万分按没反应"）

### 根因
旧逻辑用**显示积分 + 已消耗档位**倒推资格（`score >= (nuke_tier+1)*30000`，且档位在"放的时候"才更新）——显示分、档位、实际可用性三处各算一遍，任何一处不同步就出现"提示可用但按了没反应"或"过了 3 万一直提示可用"。

### 改法（按你的设计）
- 新增**隐藏可用积分** `p["bank"]`：所有积分入账（伤害/击杀/助攻/救援/中和/拆缓冲）都**同时**加到显示分与隐藏分（统一入口 `_add_score()`）。
- 一切"要扣积分"的行为只看隐藏分：`can_spend(p, cost)` / `spend_points(p, cost)`。
- 氟泄漏：隐藏分 ≥ 30000 → 可用，**放完直接扣 30000**；引爆中不可再用。
- `nk_ok`（HUD 的"F 泄漏就绪"）只读隐藏分。
- **隐藏分不出现在任何 UI**；`/status.json` 也不暴露它（只暴露一个 0/1 的 `tut` 字段给验收脚本），避免被"读接口当外挂"。显示积分仍用于排名，不因放核弹而减少。

### 验证
```
node tests/v13_server_check.py → 22/22：
  2 万分不可用 / 3 万分可用 / 放完隐藏分归零而显示分不变 / 29999 时不可用 /
  再攒到第二个 3 万（总 60 万分位）又能放 / 引爆中不可用 / 教程免疫与解除 / 教程按 IP 落盘
```

## 5. 已知限制（如实写）

1. **无法在机房的实机上诊断**：以上数据来自本机（无头 Edge + 本机 Python）。若机房机器仍然卡，请让我看 HUD 左上角的 `FPS / ms / 插值` 读数：若 `FPS` 低而 `插值` 正常 → 是 GPU 填充率（会继续降 DPR/减特效）；若 `FPS` 正常但"不跟手" → 是网络（WiFi 抖动，可看插值毫秒是否变大）。
2. 60Hz 让快照流量翻倍（约 2.7KB×60 ≈ 160KB/s/客户端），局域网无压力；若有老式 WiFi 可 `--tick 30` 回退。
3. 教程是**独立小局**：每个教程玩家一个私有 `Game` + 独立小地图，按需创建/销毁；同一时刻多人上教程时，大厅里每个玩家各占一个 `Game`（内存很小，只多占一个模块副本 + 每局几个实体）。教程小局不跑地图轮换、不计入对战比分。
4. 手机 APK 未重新打包：本次改动在 `public/`（电脑端页面）；手机端资产仍是 v1.2 的内容，下次要手机开服用最新前端时需要重新 `assembleDebug`。
